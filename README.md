# docconvert — LaTeX → Word (GOST) pipeline

Python-based pipeline that converts a Russian-language LaTeX project (typically a thesis or coursework) into a single `.docx` formatted to ГОСТ. One `python convert.py` runs everything: xelatex → bibtex → pandoc → a chain of docx post-processing steps.

## Requirements

- Windows, Linux, or macOS
- Python ≥ 3.10
- A TeX distribution (~2 GB): **MiKTeX** (Windows) or **TeX Live** (Linux/macOS)
- `xelatex`, `bibtex`, `latexpand` on `PATH` (`latexpand` ships with MiKTeX; on Linux/macOS install it via your TeX distribution)
- **Pandoc** ≥ 3.0 and **pandoc-crossref** of the **same major version** as your `pandoc`

## Installation

### 1. TeX distribution

- **Windows**: install [MiKTeX](https://miktex.org/) and tick "always install missing packages on the fly". MiKTeX bundles `latexpand`.
- **Linux**: `sudo apt install texlive-xetex texlive-bibtex-extra texlive-fonts-extra texlive-extra-utils`
- **macOS**: install [MacTeX](https://www.tug.org/mactex/).

Verify: `xelatex --version`, `bibtex --version`, `latexpand --version`.

### 2. Pandoc + pandoc-crossref

Both tools must come from the same release line. Mismatched versions fail with `pandoc-crossref was compiled with pandoc X.Y but you have …`.

- Install Pandoc from [pandoc.org](https://pandoc.org/installing.html) **or** via `conda install -c conda-forge pandoc`.
- Download a matching `pandoc-crossref` binary from [its GitHub releases](https://github.com/lierdakil/pandoc-crossref/releases) and drop it onto `PATH`. **Do not** install it via `pip`/`apt` — those packages are rarely version-matched.

Verify: `pandoc --version` (top line shows version) and `pandoc-crossref --version` show the same major.minor.

### 3. Conda environment + Python deps

```bash
conda create -n thesis-convert python=3.11
conda activate thesis-convert
pip install -e .
```

This installs `python-docx`, `lxml`, `PyYAML`, `pybtex` and exposes a `docconvert` console script.

### 4. Sanity check

```bash
python convert.py --check-tools
```

All five tools (`xelatex`, `bibtex`, `latexpand`, `pandoc`, `pandoc-crossref`) must report a path. Fix any missing entry before continuing.

## Preparing your document

The pipeline expects every source in **`input/`**:

```
input/
├── main.tex                # \input{} all structural files from here
├── introduction.tex
├── chapter1.tex … chapter3.tex
├── conclusion.tex
├── referencat.tex          # abstract (РЕФЕРАТ section)
├── bibliography.bib
├── titlist.docx            # title page — prepared by you in Word
├── appendix_a.docx         # appendix sources (.tex or .docx, see config)
├── appendix_b.tex
└── Figures/                # all images
    ├── foo.png
    └── …
```

LaTeX conventions the pipeline depends on:

- Non-numbered structural sections (`РЕФЕРАТ`, `ВВЕДЕНИЕ`, `ЗАКЛЮЧЕНИЕ`, `СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ`) use `\section*{...}` followed by `\addcontentsline{toc}{section}{...}`.
- Chapters use numbered `\section{...}`.
- Glue chapters together via `\input{file}` (without `.tex`) from `main.tex`. **Citations are only discovered inside files that `main.tex` \input's** — appendices converted on the side cannot contribute new citation keys.
- Citations: `\cite{key}`; figures and tables: `\caption{...}` + `\label{}` / `\ref{}`. Images: `\includegraphics{Figures/foo.png}` (path relative to `input/`).
- Preamble must be XeLaTeX-compatible (Cyrillic via `fontspec` + `polyglossia` or `babel`).

The title page is **not** generated by the pipeline — you produce `input/titlist.docx` in Word (e.g. by filling in your university's template) and the pipeline prepends it as the first physical page with `titlePg` so its header/footer are independent of the main document.

## Configuration

Copy `config.example.yaml` to `config.yaml` and edit. Key fields:

```yaml
paths:
  input_dir: input            # where you keep sources
  tmp_dir: TMP                # scratch; wiped each run
  output_dir: output          # final docx files land here

main_tex: main.tex            # filename inside input_dir
bibliography_bib: bibliography.bib
output_name: thesis           # → output/thesis_2026-05-28_14-30-22.docx
cleanup_tmp: true             # remove TMP/ on success (override with --keep-tmp)

titlepage_docx: titlist.docx

appendices:                   # any number, merged in order
  - code: "ПРИЛОЖЕНИЕ А"
    title: "Графическая часть ВКР"
    source: appendix_a.docx
    convert: false            # docx — just merge as-is
  - code: "ПРИЛОЖЕНИЕ Б"
    title: "Листинги кода обучения"
    source: appendix_b.tex
    convert: true             # latexpand+pandoc, then merge

steps: { … }                  # toggle individual steps on/off
strings: { … }                # localised labels (Рисунок, Таблица, где, …)
style: { … }                  # font/size/margins for reference.docx
```

The order in which steps run is fixed by `docconvert/pipeline.py`; the `steps:` map only toggles each one. See `config.example.yaml` for every field.

## Running

```bash
python convert.py                # full pipeline
python convert.py --keep-tmp     # keep TMP/ for debugging
python convert.py --check-tools  # verify external tools, exit
python convert.py --list-steps   # print canonical step order, exit
```

Windows shortcut: `run.bat` adds MiKTeX + Strawberry Perl to `PATH`, activates the `thesis-convert` conda env, and calls `python convert.py %*`.

### Partial rebuilds

```bash
python convert.py --skip build_pdf            # skip a single step
python convert.py --only run_pandoc enforce_styles
python convert.py --from insert_toc           # run insert_toc and everything after
```

`--from` and `--only` **do not wipe** `TMP/`, so the working `TMP/thesis.docx` from a previous run must exist. Safe restart points are `build_style_template` and `run_pandoc` (each rebuilds its output from scratch). Post-processing steps are *not* idempotent — running `prepend_titlepage` twice will glue two title pages on. For a clean rebuild simply run `python convert.py` with no flags.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `xelatex not found` | TeX distribution not on `PATH`. On Windows, MiKTeX installs into `%LOCALAPPDATA%\Programs\MiKTeX\miktex\bin\x64` — `run.bat` adds this automatically. |
| `pandoc-crossref filter returned error` | Version of `pandoc-crossref` does not match `pandoc`. Re-install both from matching releases. |
| `Picture not found` from pandoc | Images must live under `input/Figures/` and `\includegraphics{}` paths must be relative to `input/`. |
| Double "Рисунок Figure" labels | Stale `crossref.yaml`. The bundled `templates/crossref.yaml` already sets Russian labels. |
| Wrong bibliography numbering | Re-run with `--from build_bibliography` (it re-reads `input/main.tex` for citation order). |
| Step fails mid-pipeline | `TMP/` is preserved. Look at `TMP/main.log`, `TMP/main_flat.tex`, or open `TMP/thesis.docx` in Word. After fixing the cause, run `python convert.py` again — `TMP/` is wiped at the start of a full run. |
| `output/` keeps growing | The pipeline never deletes finalized docx files. Clean them yourself when no longer needed. |

## Repository layout

```
docconvert/        — pipeline package (steps in docconvert/steps/)
templates/         — pandoc assets shipped with the pipeline
input/             — your sources (you edit this)
TMP/               — auto-managed scratch (do not check in)
output/            — final docx files with timestamps
config.yaml        — your active configuration
config.example.yaml — annotated template
convert.py         — CLI launcher
run.bat            — Windows convenience wrapper
```

## Known limitations

- Citation discovery only reads files that `main.tex` \input's; citations inside externally-converted appendices are invisible to the bibliography step.
- Post-processing steps modify the working docx in place — they are not safe to re-run mid-pipeline without rebuilding from `run_pandoc`.
- The title page is supplied by the user as a finished `.docx`; the pipeline does not generate it.
